# Мини-PDM: Состав изделия

Десктопное приложение для управления составом инженерных изделий и версиями по требованиям ЕСКД. Разработано для тестового задания .NET в стек АСКОН.

## Стек технологий
- Платформа: .NET 8, C# 12
- Пользовательский интерфейс: WPF, MVVM
- СУБД: PostgreSQL, MS SQL
- Доступ к данным: Dapper
- Внедрение зависимостей: Jab (генерация контейнера во время компиляции)
- Тестирование: xUnit, FluentAssertions

## Архитектура решения
Решение построено по принципам Clean Architecture с разделением на независимые слои:

- `src/MiniPdm.Domain` - ядро предметной области, правила ЕСКД, сущности, конечный автомат версий и инварианты без внешних зависимостей
- `src/MiniPdm.Application` - сценарии использования, абстракции репозиториев, модели отчета, рекурсивные расчеты массы и спецификации, сервис сравнения версий
- `src/MiniPdm.Infrastructure` - Dapper-репозитории, рекурсивные CTE-запросы, изоляция SQL-диалектов PostgreSQL и MS SQL, парсер документов САПР, экспорт в CSV
- `src/MiniPdm.UI` - графический интерфейс WPF, ViewModels, Composition Root на Jab
- `tests/MiniPdm.Tests` - модульные тесты для всех слоев решения

## Сборка и запуск

### Требования
- .NET 8 SDK
- Docker Desktop для запуска PostgreSQL или установленный экземпляр PostgreSQL / MS SQL

### Сборка и прогон тестов
```bash
# Сборка всего решения
dotnet build MiniPdm.sln

# Запуск тестов
dotnet test MiniPdm.sln
```

### Запуск базы данных
В корне репозитория подготовлен файл `docker-compose.yml`:
```bash
docker compose up -d
```
СУБД поднимется на порту 5432 с базой данных `minipdm`.

### Запуск приложения
```bash
dotnet run --project src/MiniPdm.UI/MiniPdm.UI.csproj
```

Переопределение строки подключения и провайдера возможно через переменные окружения:
- `MINIPDM_PROVIDER` - `PostgreSql` или `SqlServer` (по умолчанию `PostgreSql`)
- `MINIPDM_CONNECTION_STRING` - строка подключения к СУБД

## Хранение данных и скрипты схемы
Схема БД инициализируется автоматически при первом запуске через `DatabaseInitializer`. Скрипты создания таблиц и индексов изолированы в соответствующих диалектах:
- PostgreSQL: `src/MiniPdm.Infrastructure/Data/PostgreSqlDialect.cs`
- MS SQL: `src/MiniPdm.Infrastructure/Data/SqlServerDialect.cs`

Структура таблиц:
- `pdm_object` - объекты системы (сборки, детали, стандартные изделия)
- `object_version` - версии объектов, состояния жизненного цикла, масса и материал
- `bom_link` - связи вхождения состава изделия ("Состоит из ...") с положительным количеством
- `import_log` - журнал операций импорта

Выборка полного дерева состава выполняется одним запросом с рекурсивным CTE. В запросе реализован контроль посещенных путей `HierarchyPath`, предотвращающий зацикливание при наличии циклических ссылок.

## Принятые архитектурные решения

- Изоляция САПР через интерфейс `ICadDocumentReader`. Домен и прикладной слой не зависят от формата JSON или файловой системы.
- Value Object `Designation` для обозначений по ЕСКД с валидацией через Source Generator `[GeneratedRegex]`.
- Конечный автомат жизненного цикла версий в сущности `ItemVersion`. Переходы строго однонаправленные: `В работе` -> `Утверждено` -> `Аннулировано`. Изменение реквизитов и состава заблокировано для утвержденных версий.
- Изоляция диалектов СУБД через интерфейс `ISqlDialect`. Специфика рекурсивного CTE для PostgreSQL (`WITH RECURSIVE`) и MS SQL (`WITH`) разделена по отдельным классам.
- Компиляционный DI через Jab. Отсутствует runtime-рефлексия при резолве зависимостей.
- MVVM без логики в code-behind окон. Все действия, переходы и валидации вынесены в ViewModels.

## Отчет по импорту cad-export и cad-export-v2

### 1. Импорт cad-export
Всего файлов в наборе: 45 (12 сборок, 33 детали и стандартных изделия).

Итоги импорта:
- Принято: 41
- Отклонено: 4
- С предупреждением: 1

Выявленные ошибки и предупреждения:
1. `Отдушина.m3d` - Ошибка: Синтаксическая ошибка в JSON (пропущена запятая на строке 8). Файл отклонен.
2. `Шайба стопорная.m3d` и `Шайба упорная.m3d` - Ошибка: Дублирующееся обозначение `РДЦЛ.304112.710`. По правилу ТЗ отклонены оба файла.
3. `Пробка сливная в сборе.a3d` - Ошибка: Вхождение компонента `Пробка сливная.m3d` имеет количество 0. По правилу ТЗ отклонена вся сборка.
4. `Прокладка маслоуказателя.m3d` - Предупреждение: Не указана масса. Деталь принята в базу с предупреждением. При расчете массы сборки с этой деталью система выводит сообщение о недостающей массе.
